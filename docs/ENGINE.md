# Engine guide (for scene authors)

The engine is the workspace package `@pve/engine` (`packages/engine/`, TypeScript + three.js). The web app (`app/`, run with bun + Vite) plays one project, `projects/<id>/`, chosen with `?project=<id>`. It renders any song time `t` deterministically at 1920×1080 (or at 2× that, 3840×2160, with `?scale=2`. See "Output scale" below). The same code drives the live preview and the offline 60 fps export.

## Running things

- Preview: `cd app && bunx --bun vite`, then http://localhost:5173/?project=pdoom_original&t=23.0 (space = play/pause, ←/→ = ±1 s, shift = ±5 s, `,`/`.` = ±1 frame, `[`/`]` = previous/next timeline entry, `l` = loop the current entry, `h` = hide the UI).
- The commands are `bun run pve <command>` from the repository root (`skills/pve/SKILL.md` has the loop). Each one takes `-p <id>` (or `PVE_PROJECT`, or runs inside `projects/<id>/`). Output goes to `projects/<id>/out/`.
- Stills (LOOK at the PNGs): `bun run pve still 12.5 @loss lyric:FOOM -p pdoom_original`. Times are seconds or time expressions.
- Contact sheets: `bun run pve look open -p pdoom_original` (12 tiles inside the clip), `pve look cuts` (both sides of every cut), `pve look` (the whole song). Each tile shows its time, clip and bar.beat.
- A range as video (to judge motion): `bun run pve render --from @hook1 --to @room -p pdoom_original`.
- Typecheck: `bun run typecheck` (the app config includes `projects/*/video/scenes`). `bun run pve check` is the fast check (schema, expressions, compile, banned calls, missing features).
- The render commands print `SCENE ERRORS` and browser console errors. A console error (a shader that does not compile, a scene that throws) makes `still`, `look`, `bench` and `render` fail.
- 4K: add `--scale 2` to `still`, `look` or `render` (`still` then saves full-resolution 3840×2160 PNGs). Check your scene at both scales: downscaled, the 4K frame should look like the 1080p one, only sharper.
- The commands use the dev server at http://localhost:5173 if it answers, else they start a private one without live reload. A live-reloading server reloads the page when a file changes, so do not edit files during a render on it. Headless commands always start their own server unless `--url` is given. Chrome runs with a persistent profile from a pool of 8: a command takes the first free one, so commands run side by side, and it fails at once when all are busy. A page step that takes too long (`PVE_READY_TIMEOUT` seconds for boot and scene init, default 60; `PVE_FRAME_TIMEOUT` for one frame, default 30) fails the command with exit code 1: a scene that loops is a bug in the scene.
- Headless Chrome renders WebGL on ANGLE over D3D11 on Windows (Metal on macOS). A fault that only one browser setup shows can come from its ANGLE backend: look at "GL_RENDERER" on `chrome://gpu`. `PVE_ANGLE=<backend>` (for example `gl`, `vulkan`, `d3d11`) makes the commands render on that backend, so `PVE_ANGLE=gl bun run pve still 57.5 -p sardine` shows the frame as a Chrome with `--use-angle=gl` draws it.

## Data

- `lyrics` (`@pve/engine/lyrics`): `lines[]` with `i,text,start,end,words[]`, each word `{w,start,end,syl?,line,index,gi}` (word-level, aligned to the vocal, where `syl` holds `[start, end]` per syllable on words with two or more). Find lines by content, never hard-code times: `const l = this.ctx.lyrics.get('sudden drop')` → `l.words[3].start` (`get` throws when the text is missing, and `get(text, n)` takes the n-th match). Queries: `find(text)` (all matching lines), `linesIn(t0, t1)` (the lines of a clip: `linesIn(ctx.start, ctx.end)`), `lineAt(t)`, `lastLine(t)`, `nextLine(t)`, `wordAt(t)`, `lastWord(t)`, `findWords('P(doom)')`. Helpers: `Lyrics.wordProgress(word, t)` (0..1 sung progress, by syllable when known), `Lyrics.lineCharProgress(line, t)` (chars sung so far — for per-glyph wipes).
- A song with `user_input/lyrics.map.json` gives each line `written` (`LineWritten` in `lyrics.ts`): `jp` and `en` (the written lines), `units` (each Japanese glyph with the syllables it is sung on: `from`, `to` index `syllables(line)`, with `start`, `end`), `phrases` (each English phrase with `from`, `to`, `loose`, `start`, `end`) and `ghosts` (indexes of sync-only syllables, never draw them). Without a map, `written` is undefined.
- `audio` (`@pve/engine/audio`): `beats[]`, `downbeats[]`, `sections[]`, `beatAt(t)` (continuous beat index), `barAt(t)`, `timeOfBeat(i)`, `nearestBeat(t)`, `events('kick'|'snare'|'hat'|'vocal', t0, t1)`, `env(name, t)` for `rms|low|mid|high|vocal|drums|bass|other` (0..1), `hit(kind, t, halfLife)` decaying pulses. A song has the stem envelopes and the onset kinds that Lyric-Sync computed: `pve check` names each one that a scene reads and the song lacks.
- Every `Frame` carries `f.a` = `{rms,low,mid,high,vocal,drums,bass,other,kick,snare,hat,vonset}`, and `f.beat`, `f.bar` (continuous indices: 12.5 is half way from beat 12 to beat 13, beat 0 is the first beat, and bar 0 is the first downbeat) with `f.beatPhase`, `f.barPhase` (their fractional parts, 0..1).
- Palette keys (`rgba(key)`, `LIN[key]`, GLSL `C_<KEY>`): `ink` (background black), `ink2` (raised black), `graphite` (dim lines), `ash` (mid grey), `bone` (paper white, primary text), `signal` (hazard orange), `ember` (light orange), `blood` (deep red-orange), `acid` (rare accent). A project replaces them in `video/assets/palette.json`.

## Writing a scene

One file `projects/<id>/video/scenes/<name>.ts`, default-exporting a class extending `Scene` (`@pve/engine/scene`). A clip in `video/video.json` names it with `"scene": "<name>"`. A clip without a `scene` renders the storyboard card (`@pve/engine/storyboard`: clip id, `brief`, bar.beat with a beat pulse, the lyric line sung now).

```ts
import * as THREE from 'three';
import { Scene, type Frame } from '@pve/engine/scene';
import { FSPass, Layer2D, W, H, clearRT } from '@pve/engine/gl';

export default class MyScene extends Scene {
  bg = new FSPass(`uniform float t; void main(){ fragColor = vec4(C_INK, 1.0); }`, { t: { value: 0 } });
  text = new Layer2D();
  async init() { /* build geometry, precompute text outlines, etc. */ }
  render(f: Frame, out: THREE.WebGLRenderTarget) {
    const { renderer, comp, lyrics } = this.ctx;
    this.bg.u.t!.value = f.t;
    this.bg.render(renderer, out);            // fullscreen shader → out (overwrites)
    const c = this.text.ctx; this.text.clear(); /* draw with Canvas2D */
    comp.draw(renderer, this.text.upload(), out); // alpha-over onto out
    return { bloom: 0.7 };                   // post overrides (optional)
  }
}
```

Rules:

- **Deterministic**: output must be a pure function of `f.t` (and seeded randomness: `mulberry32(seed)`, `hash(...)`). Never use `Math.random()`, `Date.now()` or `performance.now()` for visuals. The export averages many sub-frames per frame in any order (see "Motion blur and sampling"). If you need simulation state (particles, feedback buffers), set `stateful = true`, reset in `reset()`, and integrate with `f.dt`. The engine fast-forwards after seeks. Such a scene can only be exported with a fixed `--samples`.
- `render()` must fully overwrite `out` (a HalfFloat linear-HDR target). Colours are **linear**. Values > ~0.85 bloom. Use palette constants (`C_INK`, `C_BONE`, `C_SIGNAL` in GLSL, `LIN.signal` in TS for GL, and `rgba('signal', a)` for Canvas2D).
- `ctx.params` holds the timeline entry parameters (one module can serve several entries). `ctx.start/ctx.end` holds its window. `ctx.assets` holds the URL of the project `video/assets/` folder (with a trailing slash) for textures and data files. `f.lt`/`f.p` tracks local time and progress.
- Transitions: by default the engine crossfades overlapping entries. For custom transitions set `handlesTransition = true` and composite `f.under` (the previous scene's frame) yourself using `f.tin` (0→1 over the overlap). Most cuts should be hard cuts on downbeats (no overlap) — that's the default when windows touch.
- Post overrides you can return: `exposure, bloom, bloomThreshold, bloomKnee, bloomRadius, halation, ca, grain, vignette, hud (HUD opacity), frame (crop marks), paper, fade, flash, shake:[x,y], zoom, invert, overlay` (values for the project overlay, see below). Defaults in `packages/engine/src/post.ts`.
- Performance: the median scene cost at preview scale must stay under 16.7 ms (60 fps live preview). `bun run pve bench <clip>` measures it on the GPU and prints it against this budget. Canvas2D layers cost a texture upload each (`layer2d.upload` in `bench/results.jsonl`). Do not use more than 2–3 per scene. Precompute in `init()`.
- The studio loads every clip behind the loading screen. When an agent edits a scene, the studio reloads that clip while the UI shows. An `init()` that does not wait blocks the UI for its full time. Put `await this.ctx.slice()` between the heavy steps of `init()` (bakes, geometry builds). The reload then stops there until a frame has time to spare. Exports and the loading screen never wait at `slice()`.
- Wrap slow, pure work of `init()` in `await this.ctx.memo(name, () => ...)` (boid bakes, cut geometry as typed arrays). The studio keeps the result in IndexedDB and uses it on the next load while the scene code (and the files it imports), the engine, the project inputs, the assets and the clip params stay the same. Physics `bake()` does this by itself. Exports always compute.
- `bun run pve perf [clip...]` plays the clips as the preview does, one frame per animation frame. It prints the CPU time of each frame and the frames that missed a refresh. Use it for Canvas2D work. `bench` samples a few frames on the GPU only. A scene that draws a full page in Canvas2D on every frame can pass `bench` and still drop frames. `--profile` lists the functions with the most CPU time. To debug a spike fast, add `--from` and `--to` (seconds or expressions like `bar:13`). Add `--frames` to print every frame, or `--slow <ms>` to filter slow frames only. In the software canvas, drawing is deferred: the raster of a frame shows in `texSubImage2D` (the upload) or in the first `drawImage` that reads the canvas.
- Make every helper canvas a CPU canvas like `Layer2D` (`getContext('2d', { willReadFrequently: true })`). A `drawImage` from a GPU canvas into a CPU canvas reads the pixels back from the GPU.
- Write your scene files (and helper files named `scenes/<name>-*.ts` or `scenes/_*.ts`), `video/video.json` and `video/assets/`. Do not edit the engine (`packages/`): report what you need instead.

## Project overlay and assets

- `video.json` `"overlay": "<name>"` names a module in `video/scenes/` that default-exports a class extending `Overlay` (`@pve/engine/scene`). One instance draws over every clip into the HUD layer (Canvas2D, logical px), after the crop marks: `draw(c, t, { paper, params })`. `params` are the `overlay` post overrides of the active scene. pdoom's corner P(doom) gauge is `projects/pdoom_original/video/scenes/hud.ts` (shown with `{ overlay: { gauge: 1 } }`).
- `video/assets/palette.json` replaces palette colours by key (`{ "signal": "#22C3FF" }`, keys of `DEFAULT_HEX` in `palette.ts`). The page applies it before the engine modules load, so `HEX`, `LIN`, `rgba()` and the GLSL constants all use it.
- `video/assets/fonts/<path>` replaces the engine font file `app/public/fonts/<path>` of the same path (e.g. `fonts/src/IBMPlexMono-Regular.ttf`, `fonts/stroke/EMSAllure.svg`). The family names do not change.

## Toolbox

- `gl.ts`: `FSPass(frag, uniforms)` fullscreen GLSL3 pass (has `vUv`, writes `fragColor`, gets `GLSL_COMMON`), `Compositor` via `this.ctx.comp.draw(renderer, tex, target, {mode:'normal'|'add'|'screen'|'multiply'|'max', opacity, tint, scale, offset})`, `Layer2D` (1920×1080 logical Canvas2D → sRGB texture), `makeRT()` (screen-sized HDR target, where `makeRT(w, h)` takes logical px), `clearRT(renderer, rt, [r,g,b])`, `SCALE`/`PW`/`PH` (output scale and physical size).
- `glsl/common.ts` (`GLSL_COMMON`, prepended to FSPass, import it into your own ShaderMaterials): palette consts `C_INK`, `C_BONE`, `C_SIGNAL`, `sat(x)`, `remap(x,a,b,c,d)`, `rot2(angle)` (mat2), `luma(rgb)`, hashes `hash11(float)`, `hash12(vec2)`, `hash22(vec2)`, `hash13(vec3)`, `hash33(vec3)` (0..1), `snoise(vec2|vec3)` (-1..1), `fbm(vec2|vec3 p, int octaves)` (the octave count is required), `curl2(vec2 p, float t)`, 2D SDFs `sdCircle(p, r)`, `sdBox(p, halfSize)`, `sdSegment(p, a, b)`, 3D `sdSphere`, `sdBox3`, `sdCapsule(p, a, b, r)`, `sdTorus(p, vec2(R, r))`, `smin/smax(a, b, k)`, `aaFill(d)`, `aaStroke(d, width)`, **`hatch(u, darkness)` and `engrave(uv, darkness, freq, angle)`** for engraving-style shading (`hatchD(u, darkness, du)` takes the derivative of `u` from the caller, for a coordinate whose `fwidth` lies, such as an angle that wraps), `halftoneDots(p, cell, angle, darkness)` / `dots(p, cell, angle, darkness)` for anti-aliased dot screens, `heat(x)` orange ramp, `toSRGB/toLinear`. A shader that does not compile fails `pve still`, `look` and `bench` with the GLSL error.
- `lines.ts`: `LineBatch(capacity, {screen2D, worldWidth, blend})` — GPU capsule segments, 2D pixels (y down) or 3D with a camera. `seg2`, `seg`, `polyline`, `render(renderer, out, camera?)`. Colours linear, can exceed 1 for glow. Good for 10k–200k segments.
- `type.ts`: fonts. `F.archivo(width 62–125, weight 300–900)` (grotesk with width steps 62/75/87.5/100/112.5/125), `F.archivoItalic()`, `F.serif(weight, italic)` (Cormorant Garamond), `F.mono(weight, italic)` (IBM Plex Mono). `font(family, px)` → CSS font string. `layout(text, family, size, tracking)` → `{ text, family, size, width, ascent, descent, glyphs: [{ ch, i, x, w }] }` with the font kerning (draw glyph i at `glyphs[i].x`, `w` is its advance). `glyphX(text, i, family, size)` → where to start drawing `text[i..]` when a word is drawn in pieces (sung or unsung colours, wipes). Never offset a piece by `measure(text.slice(0, i))`, which drops the kern between the pieces. `fitSize(text, family, maxWidth, max)` (largest size that fits), `measure(text, family, size, tracking)` (width in px), `textPath2D` (opentype outline as Path2D), `textPathCommands`, `textPoints(text, family, size, step)` (points filling the glyphs — "text made of atoms"). `smart(s)` / `plain(s)`: typewriter quotes → typographic (’ “ ” …) and back.
- `stroke.ts`: single-stroke plotter/engraving fonts (`script`, `hscript`, `sans`, `readable`, `tech`, `serif`, `osmotron`, `felix`): `strokeText(text, font, size, tracking, kern)`, `drawStrokeText(ctx2d, st, lengthPx)` → returns pen head position, `writtenLength(st, charTimes, t)` to sync writing to word timings. The fonts have no kerning tables: pairs that leave a hole (To, Yo, We, AV, LT…) are kerned optically from the glyph shapes (off for the connected scripts). Path tools: `parseSvgPathD`, `resamplePolyline`, `polylineArcLength`, `smoothBuffer(arr, passes)`.

## Typography

- Proportional text gets the font kerning: whole strings through Canvas2D get it automatically. Glyph-by-glyph drawing must use `layout()` / `glyphX()`. Adjacent runs in different fonts or sizes have no kerning between them. Set that gap by eye.
- Lyrics come with typographic punctuation (`don’t`, `’cause`, `“Just`): `Word.w` and `Line.text` go through `smart()`, and `lyrics.get()` matches straight or curly quotes. Hardcoded display strings use ’ “ ” … – — × − too. Mono text (IBM Plex Mono) is the UI/terminal voice and keeps typewriter quotes (`plain()` for a lyric shown as typed input).
- No outlined or haloed type.
- `util.ts`: `clamp, lerp, remap, smoothstep, ease.*, prog(x,a,b,ease), keys(t, [[t,v,ease],...]), springStep, pulse, mulberry32, hash, noise1/2/3, fbm1/2, polylineLengths, pointAtLength, window01, pad0, formatTime, cameraDistance, roundRectFill`. `hashSin(a, b)` is the sine hash fract(sin(a·127.1 + b·311.7)·43758.5453). It is a different hash from `hash`. `clampMinMax(u, a, b)` is Math.max(a, Math.min(b, u)): it gives a when a > b.
- `hud.ts`: the global HUD layer: crop marks (post `frame`, ink on `paper`) and the project overlay.

## The lit low-poly kit

These modules make a low-poly world in real light. The world renders into a logical frame of 640×360 px (`LW`, `LH` = `W / 3`, `H / 3`). The output pass scales it ×3 with nearest sampling to the 1920×1080 frame.

- `lit.ts`: the parts of the world.
  - `LitAtlas(size)`: one RGBA texture of colour cells. Alpha 255 is a lit texel, alpha 1..127 is an emissive texel (strength 0..`EMIT_MAX`), alpha 0 is clear. `paint(w, h, fn)`, `repaint(cell, fn)` (not on each frame: it uploads the full atlas), `solid(col, emit)`, `canvas(w, h, draw)`. `flat` gives the far atlas (one mean colour for each cell). `wrong(seed)` gives an atlas where each cell shows the texels of another cell.
  - `Painter`: `px`, `clear`, `rect`, `fill`, `speckle`, `sink` (a PixelFont sink).
  - `Builder(tex)`: flat-shaded geometry with an atlas cell on each vertex. `quad`, `tri`, `box(w, h, d, faces, m)`, `extrude`, `cylinder`, `sweep`, `geometry()`. A `Face` is `{ cell, map: 'tile' | 'fit' }`. A tile face repeats its cell at `tex` texels per metre. A fit face stretches its cell once. Helpers: `allFaces(face)`, `at(x, y, z, ry)` (a matrix), `v3(x, y, z)`.
  - `litMaterial(atlas, { side, tint, extra, mips, mipBias })`: Lambert with flat shading that reads the atlas cell with texelFetch. `extra` (`LitExtra`) adds shader code: vertex and fragment declarations, a vertex body and an emission term. `setLitLod(m, far)` and `setLitTexture(m, tex)` change the atlas texture of a material. `litMesh(builder, mat, { cast, receive })`. `screenMaterial(tex, strength)` shows a texture as light.
  - **Mipmaps.** The atlas reads its texels with nearest sampling. When a surface shows more than one texel in a pixel (a ground seen from a zoomed-out map), a fine pattern beats into moire. `atlas.mipmap(cell)` gives a cell copies at 1/2, 1/4 and 1/8 resolution. Each copy shrinks the cell by itself, and its blocks wrap round inside the cell, so no colour of a neighbour cell comes in. A material made with `mips: true` reads its cells through these copies: the level is log2 of the texels in one pixel (from `dFdx`/`dFdy` before the wrap into the cell), and the two nearest levels blend, so a zoom moves smoothly. Every cell that such a material draws must be mipmapped. `mipBias` adds to the level: with 1, a texel that covers one pixel already reads the next level. Use it for strokes one texel wide (letters), which drop out and come back from frame to frame at one texel a pixel. The copies mix the colour of a block but keep the emission strength of each texel, so paint an emissive cell with one strength. Use mips only for the surfaces that need them (sardine: `GameWorld.groundMat` for the ground, the pit tiles and the mountain, and the destination boxes of the train with `mipBias` 1). It has a program of its own (`lit-mip`), and the other lit materials keep the plain shader.
  - Do not put the mip code into the shared lit shader. On ANGLE over OpenGL (Chrome with `--use-angle=gl`), the bridge flowers of sardine got black edges when the shared shader had the mip code. The branch did not run for their cells. D3D11 ANGLE and Firefox showed no fault. A scene that changes the material of the world must change `groundMat` too (`mapLod`, the interlude glitch, the chorus 3 map and copies).
  - Lights: `point`, `spot`, `sun(col, intensity, half, size)` (a directional light with a square shadow of `half` metres), `ambient(sky, ground, intensity)`, `enableShadows(renderer)` (PCF). `camera(fov, near, far)` has the 16:9 aspect.
  - `markObject(name, obj, cam, rect)` records the screen box of a 3D object as a mark for `pve probe`.
  - Colours are sRGB hex (`Col`: `'#rrggbb'` or a number). `col(c)` gives a linear `THREE.Color`. `rgb8(c)` gives the bytes.
- `litview.ts`: `LitView(w, h)`: one view of the world. `render(renderer, scene, cam, sky)` draws the `Sky` (zenith, horizon, ground, stars, a sun or moon body with an optional corona) and then the scene into a HalfFloat target. `renderInFront` draws a second scene in front of it. `renderOver` draws a scene into an overlay over the interface layer. `present(renderer, target, output, text, x, y, w, h)` runs the bloom chain and the output pass: ACES tone map, the text layer, an ordered dither at `levels` steps, an optional CRT bend (`crt` 0..1) and a fade. `toScreen` writes the picture without dither into `screen`, a texture for a screen in another view. A view of another size than 640×360 is a window view: it has no bloom and no output pass.
  - **Precision.** The HDR target is a 16-bit float target (less memory, faster). With `?hdr=float` in the page address it is a 32-bit float target. At 16 bits the GPU does not always round an additive blend the same way. The same draw with the same inputs can give a value that is one 16-bit step higher in some texels. The dither of the output pass then moves a few pixels by one level step (a difference of about 11 in an 8-bit channel at 24 levels, in less than 0.1 % of the pixels). The difference comes and goes with the frames that the page rendered before. Thus it looks like a frame that depends on the render order, but it is not one. At 32 bits the step is too small to reach the dither.
  - **Checks at both precisions.** `bun scripts/determinism.ts` renders at 32 bits, then at 16 bits. A difference at 32 bits is a true order fault and the check fails. A difference at 16 bits, at a time that is right at 32 bits, is a precision difference: the check reports it and does not fail. Do the same when you compare stills by pixel: a difference of one level step in scattered pixels of a frame with additive glow is this rounding. To make sure, run `bun run pve order -p <id> <time> <times before it> --precision float`. The engine renders at 16 bits. The 32-bit target is for the checks only.
  - `posedOnce(renderer, scene, draw)` runs the renders of one frame of a posed scene through more than one camera (the windows of the frame). It makes the world matrices of the scene once, before `draw`. It makes the shadow maps once, in the first render of `draw`. Without it, each render makes both again. In `draw`, move cameras only. Do not move, show or hide an object or a light of the scene. Do not render another scene that has lights with shadows.
- `textlayer.ts`: `TextLayer(w, h, colorSpace)`: an RGBA DataTexture, x right and y down, sRGB bytes. The default is the 640×360 interface layer of a `LitView` (NoColorSpace). A small layer with SRGBColorSpace is text that is painted on a 3D object. `put`, `rect`, `shade` (darkens a rectangle), `sink` (a PixelFont sink), `clear`, `commit` (marks the texture for upload). `words` is the same data as one 32-bit word for each texel (r, g << 8, b << 16, a << 24): a loop that writes many texels writes words.
- `track.ts`: railway track along a `THREE.Curve`. `buildTrack(atlas, path, opts)` returns a Builder with two rails, sleepers and a ballast bed. The rail tops lie on the curve. Options: `up(u)` (a twist along the track), `twoSided` (rails and sleepers on the underside too, a Möbius track), `closed`, `step`, `sleeperGap`, `sleepers`, `ballast`, `faces`. The sizes are options too: `gauge` (default 1.067 m), `railDepth`, `railHead`, `railWeb`, `railHeadDepth`, `sleeperTop`, `sleeperBottom`, `sleeperLength`, `sleeperWidth`, `bedBottom`. `trackFaces(atlas, colours)` paints the rail, sleeper and ballast cells once (default `TRACK_COLOURS`). Give the result as `faces` to a track that you build again and again, because each paint takes atlas space. `frameAt(path, up, u)` gives the `TrackFrame` (position, tangent, side, up) at u. `frameMatrix(frame, dt, dy, ds)` puts a Builder box on that frame.
- `ui.ts`: `Ui(layer, font)`: pixel interface drawing on a `TextLayer`. `rect`, `line` (Bresenham), `ring`, `circle`, `text(s, x, y, ink, edge, n)` (pixel text with a 1 px outline, each pixel an n×n block), `textWidth`, `bevel`, `key(x, y, w, h, state, flat)` (a push button with 1 px edges; `KeyState` is `up`, `hover`, `down` or `on`), `button(x, y, state, icon)` (a flat 20×18 toolbar button), `arrow(x, y)` (the arrow cursor). A project draws its own icons with these calls.
- More helpers of `lit.ts`: `instanced(geo, mat, n, { color })` makes an InstancedMesh that is never frustum culled. With `color` it also has an `instanceColor` buffer of zeros (`setColorAt` alone makes a buffer of ones). `glowMaterial(side)` is an unlit additive material without depth write, fog or tone mapping (double sided by default). `icosphere(builder, r, face, m, sy)` adds a low-poly ball (an icosahedron) that is squashed to `sy` in height.
  - **Programs.** three keeps the program of a material for the kind of object that it drew last, and finds it again at each change. Two rules keep that cheap. `glowMaterial` is drawn in one pass (`forceSinglePass`): three draws a transparent two-sided material twice and finds its program again each time. `instanced` gives the mesh its own depth materials for the shadow pass: three has one depth material for all casters, and it changes between meshes and instanced meshes. `bun run pve perf <clip> --draws` counts the program lookups by cause, and it lists the programs that three made in the walk. The GPU makes a program ready at its first draw, not when three compiles it: a scene draws one frame of each of its parts at init (`warmFrames`), so no frame of the clip pays for that.
- `util.ts` has `projectToRect(q, rect)`: it changes a point in normalized device coordinates (for example from `Vector3.project`) to whole pixels of the rectangle `[x, y, w, h]`. `DEG` is the number of radians in one degree.
- `blendcam.ts`: `BlendCamera` is a `PerspectiveCamera` whose projection is a blend with the orthographic projection of the same frame. `mix` 0 is orthographic (the frame `2 * aimDist * tan(fov / 2)` high at the distance `aimDist`), 1 is the plain perspective. Both put the plane at `aimDist` at the same place in the picture, so a move from an orthographic map camera into the world has no jump. The blend lives in `updateProjectionMatrix`, which `LitView.render` calls.
- `mosh.ts`: `Mosh` is a datamosh. `start(renderer, key)` starts the chain on a 640×360 key picture. `step(renderer, scene, cam, prev, rect)` moves the chain one frame along the camera motion from `prev` to `cam` inside the window `rect` (a position pass of the posed scene and a warp). `present(renderer, out, pic, u)` writes the clean picture with the chain over it, dissolved pixel by pixel by `u` (0..1). A frame of the mosh is the chain of all frames since the key frame: the caller steps from the key frame to the frame. `litview.ts` exports `UNSHOULDER_GLSL` (`toLin` and `unshoulder`, the inverse of the output tone shoulder) for passes that write display colours into a frame.
- `textmode.ts`: `TextMode(frame)` turns the picture into a text mode of 4×6 px character cells (`CELL_W`, `CELL_H`, `COLS`, `ROWS`) in shades of one blue. `read(renderer, src)` takes an HDR picture down to the grid and reads it back. `draw(layer, collapse)` writes the grid into a 640×360 `TextLayer`. A `Collapse` (`scale`, `slide(row)`, `drop(row)`) makes the characters bigger and moves rows; `WHOLE` is the grid as it is. `burst(layer, x, y, r, tau, seed)` explodes a disc into characters; `frame` is the length of a video frame, and the disc holds for 2 frames before it flies.
- `chunks.ts`: a world that unloads in chunks. `ChunkGrid({ x, z, x0, nix, niz, iz0, pivotY, check })` is the grid; its values are templated into the shader, and `key` is part of the program cache key. `chunkArrays` / `chunkedGeometry` / `chunkGeometry(grid, src, matrix, kind, keep)` cut a Builder geometry into chunks (`aChunk` = ix, iz, kind), `chunkTree` replaces every plain mesh under a root by its cut copy. `Unload(grid, worldTime, trackTime, farTime)` holds the unload time of every chunk for each kind (0, 1, 2) in a float texture; `unloadMaterial(atlas, unload, load)` is the lit material that shows the missing-texture checker for `check` s and then drops the chunk, tumbling, and `load` is an optional load wave. `Unload.xf` is the same motion in JS for instances. `NEVER` is the time of a place that never unloads.
- `crt.ts`: `CrtTube` is the 4:3 glass (`TUBE_W`×`TUBE_H`, 640×480) of a CRT in a lit room. `draw(renderer, picture, opts)` letterboxes the 640×360 picture in its middle rows, puts an optional `title` layer over it and warms the tube up (`power`). `fit` writes the picture through the inverse of the room's ACES and the tone shoulder, so the glass that fills the frame shows the picture exactly. `TUBE_PLAIN` is the tube fully open with no title and no fit. `plotGlassCrack(layer, o)` plots the cracks of a hit at the pixel `o`.
- A scene of this kit returns `NO_FILM_POST` (`post.ts`) from `render`: it turns off bloom, halation, chromatic aberration, grain, vignette, HUD and frame, so the engine post does not soften the pixels.

## Output scale (4K)

`?scale=2` (`--scale 2` on `pve still`, `look`, `render`) renders a true 3840×2160 frame. Scenes keep laying out in logical 1920×1080 px (`W`, `H`, `ctx.W`, `ctx.H` never change). The engine handles the rest:

- Render targets: `out`, the engine targets and `makeRT()` are physical (`PW`×`PH`). `makeRT(w, h)` takes logical px and allocates `w*SCALE`×`h*SCALE`. Pass `{ pxScale: 1 }` for a data-sized target whose resolution must not follow the output.
- `Layer2D`: the backing canvas is `SCALE`× larger and its context is pre-scaled, so drawing code works in logical px. `setTransform`/`resetTransform`/`getTransform`, `shadowBlur`, `shadowOffsetX/Y` and `filter` px lengths are patched to stay logical. Not patched: `canvas.width/height` and `getImageData`/`putImageData` are physical px, and `drawImage(layer.canvas, x, y)` needs an explicit size. `new Layer2D(w, h, 1)` makes a deliberately low-res layer (e.g. a soft glow). `scaleContext2D(ctx, SCALE)` applies the same patch to your own canvas.
- `LineBatch`: coordinates and widths stay logical. The AA feather and hairline floor work in physical px, so hairlines stay crisp.
- GLSL (`GLSL_COMMON`): `gl_FragCoord`, `fwidth` and `dFdx` are physical. Use `FRAG_PX` (the fragment position in logical px) instead of `gl_FragCoord.xy` whenever it is combined with logical sizes, and `PX_SCALE` to convert. A line whose width comes from `fwidth` ("a 1.2 px hairline": `1.0 - smoothstep(a, b, d / fwidth(u))`) gets thinner and fainter at 4K: write it as `pxLine(d, a, b)`, which is identical at 1× and keeps the 1× ink with sharper edges at 4K (`rampLine` does the same for the linear-ramp idiom). `hatch`, `engrave` and `aaStroke` already do this. LOD thresholds and supersampling offsets expressed in pixels should be logical (`fwidth(u) * PX_SCALE`, offsets `/ PX_SCALE`).
- Offscreen canvases used as textures (atlases, text planes) keep their own size: make them `SCALE`× larger (with `ctx.scale(SCALE, SCALE)`) if they are shown large, or they look soft at 4K.
- Post (bloom, halation, CA, grain, vignette) and the HUD scale automatically. The bloom pyramid stays at the logical resolution.
- Half scale: `?scale=0.5` renders 960×540 (the web player offers it for slow GPUs, see `docs/SITE.md`). It is for viewing only: `still`, `look` and `render` take whole numbers. `SCALE` is 0.5 or a whole number from 1 to 4. The `SCALE === 1` shader branches are the 1× look, so every other value takes the physical-footprint branches. A line thinner than one physical px keeps its ink but gets fainter.

## Motion blur and sampling

The export renders every frame as the average of many sub-frames spread over the shutter (`--shutter 0.2`: a fifth of the frame time, centred on the frame time) before post-processing. `--samples N` takes N evenly spaced sub-frames. `--samples auto` chooses the count per 32×32-logical-px tile (`Engine.render`, `AdaptiveSampling`):

- The count steps through 4, 12, 36, 108, 324. Each step adds a sub-frame either side of every existing one, so each set is evenly spread and centred on the frame's time.
- After each step the engine compares the new sub-frames average with the old one (displayed values, worst 2×2-logical-px block). Stepped copies of a moving edge differ between the two sets, while a converged streak or a still image does not. Stepping shrinks as 1/count, so the remaining error is about half the change the last step made. A tile stops when that is below `--tol` (default 3 levels of 255) in it and its 8 neighbours. A tile that has stopped is final: it is the average of its first n sub-frames, the image the per-frame sampler would give had it stopped at n.
- Later sub-frames skip the tiles that have stopped: the engine writes the tiles still refining into the depth buffer of its targets, and while it renders a sub-frame every draw into them is depth-tested against that mask, whatever the material says, so the GPU rejects the stopped tiles before shading them (early-Z, as a stencil test does not reject early on Apple GPUs). The final average weighs each tile by its own count.
- In practice a still frame stops at 12, ordinary camera motion at 36, and whips, slams and fast zooms at 108 or 324. At 1:1 in 4K, 108 can't be told from 324, while 36 still shows faint striations on the fastest edges.
- `refine: 'frame'` (`--refine frame`) decides for the whole frame at once, as before tiles: every tile then takes the count its worst tile needs.

What this asks of scenes:

- Sub-frames render out of time order and in any number. Scene output must depend on `f.t` only. `stateful` scenes cannot sample adaptively (the engine refuses). Nothing may count `render()` calls.
- Per-frame flicker and jitter keyed to 60 fps must use `frameIdx(t)` (`util.ts`), not `Math.floor(t * 60)`. `frameIdx` is constant over the frame shutter. `floor` switches at the frame time and double-exposes two states in every frame.
- Noise that changes with continuous `t` (a hash seeded by time) is resampled in every sub-frame: it averages out, but slowly, and makes the adaptive sampler work harder. Seed it with `frameIdx(t)` unless it is meant to smooth out.
- A spark emitter whose rate varies over time passes the rate as a function of the birth time, with its maximum (`sparkParticles(..., { rate: (tb) => ..., rateMax })`). A rate read at the current `t` re-times every particle from one sub-frame to the next.
- Shaders that supersample internally (4 rotated-grid taps) take `ssTap: SS_TAP` and `${SS_TAP_GLSL}` and loop through `k` from `ssK0()` to `ssK1()` with `rgss(k)`, weighting by `ssWeight()`. The engine hands each sub-frame one tap, cycling them (every set is a multiple of 4). This averages to the same image for a quarter of the cost. In the preview and single-sample stills they take all four.
- Post parameters (shake, flash, zoom, fades, the HUD mode) are read at one point of the shutter, 1/8 of it after the frame time (where the video was tuned, and a point every sample set includes). The HUD, grain and dither draw once per frame.
- Masked tiles keep what the last sub-frame drew there. That is safe for `out` and the engine's own targets. A scene's own target keeps being drawn in full (and costs full price) unless the scene lists it in `tileMasked`: only a target with a depth buffer whose texels are read back at their own screen position or within a few px of it (`margin: 1` widens the mask by a tile), like shoggoth's half-res G-buffer, or, with `moving: true`, one read through a zoom or pan that the scene gives before each sub-frame's draws with `ctx.mapTileMask(rt, map)`, like the room at the bottom of loom's dive (`null` while it is read through the spiral). A target read through a warp or a wide blur must not be listed.
- A draw into a masked target whose material asks for its own depth test (3D with a depth buffer) can't use the mask: the engine draws that sub-frame again unmasked and keeps drawing that scene unmasked.

## Physics

`@pve/engine/physics` bakes rigid-body physics (Rapier, deterministic build). Every frame must be a pure function of song time, and frames render out of order. So a scene never steps a live world. It simulates once and then samples stored poses.

- Call `await bake(spec)` in `init()`. It steps a fixed-rate world from `t0` to `t1`, stores every pose in one `Float32Array` (7 floats per body per step: position, then quaternion x y z w), and frees the world. It uses no wall clock and no `Math.random`. The same spec gives the same bytes.
- `spec`: `{ t0, t1, hz = 120, gravity, bodies }`. A body has `shape` (`box`, `ball`, `capsule`, `hull`, or an array for a compound body, each with an optional `local` pose), `pose`, `type` (`dynamic`, `fixed`, `kinematic`), and optional `drive(t)`, `vel`, `spin`, `density`, `friction`, `restitution`, `damping`, `gravityScale`. `wakeAt` holds a dynamic body still, or on its `drive`, until that song time. Then it is released with the velocity of `drive` or with `vel` and `spin`.
- Sample with `baked.pose(i, t, p, q)`, `baked.matrix(i, t, m, scale?)` or `baked.instances(mesh, t, first?)`. Positions interpolate linearly, rotations by normalised lerp. Times outside `[t0, t1]` clamp. `baked.hit(i)` gives the song time of the first contact of body i, or `Infinity`. Use it for spark and dust cues.
- Memory: bodies × 7 × 4 bytes × hz × seconds. 1500 bodies for 4 s at 120 Hz take about 20 MB. Fixed bodies store one pose. Lower `hz` or `t1 - t0` before you drop bodies.
- Do not use three's `RapierPhysics` addon. It loads from a CDN and steps on wall-clock time.

## Object marks and probing
Scenes can annotate rendered objects with bounding boxes using `mark()` from `@pve/engine/marks`:
```ts
import { mark } from '@pve/engine/marks'
mark('word:break', x, y, width, height, [r, g, b])
```
Use `pve probe` in the CLI to inspect these marks:
- `pve probe <from..to> -t <name>` tracks an object bounding box and saves a crop strip.
- `pve probe --lyrics <clip>` verifies that sung lyrics stay inside screen bounds.

Scenes can report a value that they compute with `metric()` from `@pve/engine/marks`:
```ts
import { metric } from '@pve/engine/marks'
metric('load.u', u)          // one number
metric('car.pos', x, y, z)   // a vector
```
Metrics and cameras are bookkeeping only. They do not change the picture.
- `pve probe <from..to> --cams` lists the camera of the picture on each frame: its clip and id, its kind, its position, yaw, pitch and roll (degrees), its lens (the fov of a perspective camera, the frame height of an orthographic one) and its perspective amount (1 perspective, 0 orthographic). It also lists the step from the frame before: metres moved, degrees turned and the lens change. The camera of the picture is the one with the largest viewport. The export page records every camera that renders.
- `--all-cams` lists every camera that drew, one series each.
- `--metrics` lists the values that scenes report, with the step from the frame before. `-t <glob>` filters the names.
- `--jumps` shows only the frames where a step is more than 4 times the steps round it: a cut, a pop or a jerk. A change of camera shows as `switch`. Times step one frame by default (`--step s`).
